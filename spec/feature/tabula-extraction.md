# Tabula — 共同編集ノートへの切り出し

2026-09-26: neco の依頼「Memoriaのノートの実装をパージし、別のWebサービスとして切り出す。みんなでWebページに書き込みできるようにする」。名称は同日の「Tabulaがいいかな」で選定。

## 目的と受入条件

- ノートの保存・文書編集・注釈・コメントを専用DBとHTTPプロセスを持つ Tabula に移す。
- 複数の認証済み利用者が共有ページを書き込める。古い版での上書きは拒否し、入力を失わず競合を知らせる。
- Memoria はノートエディタとノートCRUDを所有せず、取り込み等は明示したHTTP境界で連携する。
- 既存ノートのUUID・ブロック・コメントを保持する移行を用意する。個人ノートを自動的に共同公開しない。
- 起動・再起動は本体フォルダから Excubitor 経由。テストとマージは別の実行許可に従う。

## 独立性

名称はTabula。専用repo / package / DB / HTTPプロセスを所有し、MemoriaのソースやDBを実行時にimportしない。2026-09-26の「実装開始Tbで登録」により実装と略称 `Tb` が承認され、Ccへ登録した。

同日の補足に従い、Notionのブロックベース思想は採用しない。保存・共有・競合制御の単位は文書全体。連続したHTML本文と自由配置注釈を持ち、旧ブロックは移行・取り込みの互換形式に限定する。

## 実装する境界

1. Tabula: ページ一覧・検索、連続した本文の編集、フローティング注釈、ページコメント、共有範囲、更新競合の検出。
2. Memoria: ブックマーク本体、拡張機能の設定、外部チャット記録、AI記事生成を所有する。ノート作成はTabulaへHTTPで依頼する。
3. 保存済みページの注釈: 必要なスナップショットを明示的に取り込む。TabulaからMemoriaの個人用DBやHTMLディレクトリを共有マウントしない。
4. ノート画面・CRUD・保存コードはMemoriaから撤去し、Tabulaへの入口と必要な連携だけを残す。検索・推薦・旧Hub同期のノート依存も追従させる。
5. `implementation_notes`、日記のnotes欄、AI記事の原稿は別ドメインとして扱う。今回のノートと同名だけを理由に削除しない。

## 共同書込みの振る舞い

- 認証済みメンバーが共有ノートを作成・編集・注釈できる。投稿者はサーバで認証した利用者から確定する。
- 個人用 / 共有の区別を持つ。既存データの移行先は個人用で、明示的な共有操作で公開範囲を広げる。
- 保存時は読込み版を照合する。別の人が更新済みなら上書きせず、未保存の入力を残して最新版の確認へ案内する。
- ページ本文への書込みと、自分のコメントの編集を区別する。他人のコメントのなりすまし更新を許可しない。
- 認証の実装は既存サービスの現行契約と照合する。匿名の全世界書込みを既定値にしない。

## 移行

- 元DBを読み取り専用で開き、UUID・順序・種類・装飾データ・コメント・元URLを保存する。
- 同じ移行の再実行で重複や上書きを起こさない。移行元と移行先の件数・参照整合を照合する手段を用意する。
- 移行コードの作成と、本番データ移行の実行を区別する。元DBを自動削除しない。
- 独立起動用のExcubitor catalogに本体ディレクトリを登録する。worktreeから起動しない。

## 審査時の受入項目

- Memoriaを停止した状態でもTabulaのノート編集を利用できる。
- 2利用者で同じ共有ページに書込みでき、古い版での保存が既存内容を消さない。
- 個人ノートが他利用者の一覧・検索・直接URL・APIに現れない。
- 移行後にノート、ブロック、コメントのUUIDと内容が維持される。
- Memoriaの拡張取り込み・AI記事転写が新しいHTTP境界を使う。
- Ex注入Host、公開Origin、Viewerのprefixを本番サーバと画面資産が扱う。

## 現在の状態

2026-09-26追加指示「AI記事やスクラップされたブックマーク登録も対応」: AI記事一覧から本文・タグをTabulaに登録する。既存の転写済みフラグで操作を無効化せず、同じ内容の再登録でリンクを取得できる。一般Webページもブックマーク詳細の「Tabulaに登録」から、保存HTMLの本文・メモ・要約・元URLを登録する。Chat/Notionは既存の専用抽出を使う。一般ページの本文はテキスト化し、元HTMLはsandbox表示用に保管する。登録結果のリンクを画面に表示し、失敗を成功扱いしない。

登録は個別の明示操作で非公開ページを作る。自動一括公開・既存Tabula編集の上書きはしない。同じ入力の再送は内容ハッシュで重複を抑止する。入力内容が変わった場合は別の文書を作る。

実装承認後、Tabula本体とMemoriaの切り離しを専用worktreeで実装。Memoriaの旧ノートテーブルは削除・更新せず、読み取り専用移行のために残す。新規DBには旧ノートスキーマを作成しない。

Memoriaに `TABULA_URL`（API URL）、`TABULA_PUBLIC_URL`（利用者URL）、`TABULA_IMPORT_TOKEN` を設定する。Tabula側では同じトークンと `TABULA_IMPORT_OWNER_ID`（Cernere利用者ID）を設定する。取り込みは指定所有者の非公開ページになる。Tabula未設定時は明示的に失敗し、Memoriaにノートを代替保存しない。

本番データ移行、テスト、起動、マージは未実施。Cernereのproject key `tabula` と利用者originの登録を含む起動・移行手順はTabulaのREADMEを参照する。

## Hub廃止と共有ページの追加取得

2026-09-26の指示「チェックをONにするとTabulaの記事も出てくる」「これに伴いMemoria-Hubは消します」に対応。モード切替・Hubのサーバー/認証/proxy/設定UIを撤去する。ローカルのGPS処理はlocationルーターに残す。既存DBや保存データは削除しない。

初期値OFFのチェックでTabula共有記事をブックマーク・AI記事・ノート案内へ追加表示。取得失敗時もローカル記事は残る。OFFで進行中の取得を中断し追加表示を消す。ページ本文はsandboxで表示、編集はTabulaへ移動。ローカルへの永続コピーは作らない。

両サービスに同一のTABULA_READ_TOKEN（32文字以上）を設定する。MemoriaバックエンドがTabulaのGET /api/memoria/pagesと/pages/:idをBearer認証で呼ぶ。非公開ページは一覧・本文とも返さない。認証値をブラウザへ送らない。登録用TABULA_IMPORT_TOKENとは分離する。
